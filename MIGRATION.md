# Safe migration and cutover (read before production)

The uploaded ZIP contains source code and six static artwork images, **not** live PostgreSQL rows, Netlify Blobs, environment secrets or authentication sessions. Nothing in this project has been connected to the live Netlify database. Do not claim data is migrated until verified.

1. Back up the live Netlify database with an authorized read-only export or provider-supported backup, and separately export every object from the `product-images` Netlify Blobs store using authorized credentials. Keep the original site live; record product count, settings keys, image keys and checksums. Do not paste credentials into ChatGPT or commit them.
2. Create a NEW PostgreSQL database for Django. Do not point Django migrations at the existing Netlify database. Run `python manage.py migrate` on the NEW database only.
3. Produce JSON arrays from source tables using the original columns. For example, with read-only psql on an authorized copy: `\copy (SELECT row_to_json(p) FROM products p ORDER BY id) TO 'products.ndjson'` and similarly for `settings`. Convert NDJSON to arrays in a trusted local script, store them as `export/products.json` and `export/settings.json`, and keep `export/` private. Expected keys are original snake_case SQL column names from `db/schema.ts`. Note: these JSON exports contain store contact details; protect them.
4. Run `python manage.py shell < scripts/import_exported_data.py` only after reviewing the JSON, against the empty NEW DB. Preserve original IDs and timestamps. Compare row counts, sample prices, discounts, categories, settings, and image_key references with source.
5. Export Netlify Blobs keys and bytes via the provider's authenticated SDK/API (the ZIP does not contain them). Place each image at `MEDIA_ROOT/products/<same-basename>` retaining exact key paths. Check file signatures, counts and SHA-256 checksums; never trust unvalidated user filenames. Missing images must be fixed before cutover. Use private filesystem or a durable media storage service supported by your host.
6. Set a new Django admin password with `python manage.py createsuperuser --username shopadmin` and ensure `is_staff=True`. Original Netlify HMAC cookies are intentionally NOT migrated. Log in again.
7. Run contract tests, compare source and destination JSON responses, manually test login, CSRF, create/edit/delete, image upload and images, store filtering, WhatsApp links, and `/admin/` in a staging environment. Take a second export or pause writes during final synchronization so no product edits are lost.
8. After verifying a full backup and rollback procedure, update the domain to Django and switch traffic. Keep the old Netlify deployment and backups until sign-off. Roll back DNS/traffic if problems arise; do not overwrite the source database.

**Media hosting:** Django does not serve media automatically in production. Configure a host static/media mapping or an object store, and confirm `/media/products/...` resolves. Never enable `DEBUG` in production.
